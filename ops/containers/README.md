# Transitional development containers

This contributor environment is a transitional candidate: Next.js, Node.js and TypeScript jobs provide the runtime. Rust tooling is available for development; it is not the business runtime. This scoped candidate has not yet passed a fresh clean-ref bootstrap, HTTPS/SSO, Finance browser, HMR or restart qualification. Production, staging and shared operator data are not container targets.

The scripts target only the owned `erpx-opensource-dev` Colima profile and an explicitly keyed `erpx-dev-${ERPX_DEV_WORKSPACE_KEY}` Compose project. Install the pinned toolchain image and initialize that profile first. Choose a unique lowercase checkout-and-architecture key; it selects separate source, PostgreSQL, scanner, secret and toolchain cache volumes. Use the same key for CLI and editor, with `COMPOSE_PROJECT_NAME=erpx-dev-${ERPX_DEV_WORKSPACE_KEY}`, `COMPOSE_DISABLE_ENV_FILE=1`, and `DOCKER_HOST` pointing to the owned profile. An absent key is rejected.

Run `scripts/local/dev-container up --app=finance` on the host. A fresh source volume is cloned at the host checkout's current commit from its HTTPS origin, or from explicit credential-free `ERPX_DEV_SOURCE_URL` and `ERPX_DEV_SOURCE_REF` overrides. The requested ref must exist in that remote; local uncommitted edits are not copied. `populate` performs only the service and clone steps when a contributor needs to inspect the fresh source before bootstrap. The isolated clone cannot use host credential helpers and never copies ignored files, environment files, runtime data or operator credentials; private repositories need a separately arranged contributor-accessible HTTPS source. An incomplete copy fails closed. The command runs the shared bootstrap, then starts the local gateway and prewarms Account, Apps and the selected app. The workspace exposes only loopback HTTPS `127.0.0.1:3443`; PostgreSQL, mailbox, gateway and scanner remain private. An occupied HTTPS port fails rather than stopping another service or selecting a different port. `scripts/local/dev-container start --app=<id>` reuses a healthy owned gateway and prewarms an app; `bootstrap` repeats migration/verification without reseeding completed data. `down` stops this project and preserves its volumes. `reset --confirm=<exact-key>` removes only that keyed project's source, data, secrets, local CA and caches; it is destructive.

The editor uses the same keyed Compose project and `/workspace/erpx` Linux source volume. Run host `up` first so the source and isolated service lease exist, then open `.devcontainer/devcontainer.json` with the same key. Its post-create and post-start commands use the same bootstrap and gateway entrypoints; the editor reuses the last selected app (Finance on first start), and the CLI can prewarm another app. The workspace uses an init process to reap child processes. Cargo target/registry/git, Bun cache and node_modules are keyed separately by workspace and pinned toolchain; app `.next` output resides on the keyed source volume. A bind-mount alternative and cross-architecture qualification remain future work.

Host lifecycle commands and direct service commands take the same exclusive lock for the exact workspace key before inspecting or creating a lease. A competing command fails immediately. If an interrupted command leaves `~/.colima/erpx-opensource-dev/lifecycle-locks/<key>.lock`, first verify that no lifecycle command for that key is running, then remove only that empty lock directory. Different keys have independent locks.

Bootstrap requires the private key lease in the keyed secret volume, Linux container and independent Git checkout. It rejects copied `.env` files and external runtime credentials, installs locked dependencies and provisions a fresh isolated `erpx_dev` database. Existing data requires the original private provisioning credentials, manifests and authentication secret; missing or partial state fails closed rather than regenerating database passwords. A private source-and-key-bound phase marker resumes an interrupted seed after complete provisioning; completed installations migrate and verify without reseeding. An exclusive lock rejects concurrent bootstrap or gateway start attempts. A lock left by interruption requires confirming no such process is running before removing that specific lock directory.

The exact contributor browser origins are `https://account.erpx.localhost:3443`, `https://acme.erpx.localhost:3443`, `https://northstar.erpx.localhost:3443`, and `https://erpx-internal.erpx.localhost:3443`. This candidate must verify the explicit development-only origin profile and Caddy sidecar with CA-verified health, normal HTTPS/SSO and an actual source-edit HMR check in a clean-ref, zero-volume setup. Do not point these names to public Holding hosts or silently install a CA. The gateway listens only inside the workspace at `127.0.0.1:3100`; this lifecycle neither changes Tunnel routes nor binds host port 3100. Optional hybrid PostgreSQL and a clean-ref, zero-volume onboarding journey still require separate verification.

## Contributor HTTPS candidate

The sidecar uses a pinned Caddy image and a local internal CA, stored only in this keyed project's `local-ca` volume. It proxies to workspace loopback 3100, preserves the full external Host including `:3443`, removes supplied forwarding headers and sets its own HTTPS forwarding metadata. It never requests a public certificate or installs trust on the host. Its image build context contains only `.devcontainer` configuration, with no operator credentials. See [Caddy reverse proxy documentation](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).

After startup, export only the public root certificate:

```sh
ERPX_DEV_WORKSPACE_KEY=<your-key> scripts/local/dev-container certificate > erpx-contributor-root.crt
openssl x509 -in erpx-contributor-root.crt -noout -fingerprint -sha256 -subject
```

Verify the fingerprint against your keyed container before explicitly trusting that certificate in your operating system/browser certificate manager. The script never exports the CA private key or changes trust settings. Removing a project does not remove a certificate you trusted manually; remove that trust entry yourself when retiring the project. Keep private CA volume backups private. A new CA after reset requires reviewing and trusting its new fingerprint.

Resolve the four exact `.erpx.localhost` names to loopback in your host/browser. Browsers generally resolve `.localhost` directly; when your resolver does not, add explicit loopback entries for these four names through your normal local resolver configuration. Do not use a wildcard public alias or point these names at the public Tunnel. `curl --cacert erpx-contributor-root.crt --resolve account.erpx.localhost:3443:127.0.0.1 https://account.erpx.localhost:3443/` provides an explicit resolver and CA check without modifying system settings. Public development continues through the existing native Cloudflared Tunnel and registered public hosts.

Account responses retain the shared Node account protections, including the closed legacy multi-session endpoint gate and token-free public projections.

## Synthetic Finance demo and measured development checks

The isolated CLI bootstrap adds one synthetic Finance v1 grant for the seeded Acme Company through the Commercial application command. Its fixed fixture actor, reason and immutable event identify sample data; this is not a real purchase or a runtime provider authorization path. The command requires the current private workspace lease, source-bound bootstrap phase/lock and exact isolated database configuration. It refuses conflicting existing grants or receipts and leaves other packages alone. Repeated bootstrap verifies the same result and event rather than appending a new grant. Normal user login, SSO and role/Company authorization remain required after seeding.
