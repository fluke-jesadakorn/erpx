# Code of conduct

ERPX welcomes people with different backgrounds and levels of experience. Ask clear questions, explain technical disagreements and give feedback about the work. Respect a contributor's time, identity and boundaries.

Harassment, discrimination, threats, sexualized conduct, doxxing, impersonation and deliberate disclosure of private information are unacceptable. Do not post credentials, customer records or another person's contact information. Do not use project spaces to target someone outside the project.

This policy applies to repository issues, discussions, pull requests, reviews and other spaces where someone represents ERPX. Maintainers must follow it too.

## Reporting and moderation

Report problematic content using GitHub's **Report content** or **Report abuse** action. For a confidential project report, request a private channel from [@fluke-jesadakorn](https://github.com/fluke-jesadakorn) without posting the incident details publicly. Use [SECURITY.md](SECURITY.md) for vulnerabilities. If the report concerns the maintainer or a platform-level threat, use [GitHub's independent abuse process](https://github.com/contact/report-abuse).

Maintainers may edit or remove harmful content, ask someone to change behavior, pause participation or remove access according to the seriousness and repetition of the conduct. Explain the action privately where possible and share only the minimum information needed to protect participants. Confidentiality cannot be promised when platform reporting or immediate protection requires disclosure.

Someone affected by moderation may request a review through the same private channel, explaining the facts they believe were missed. The project currently has one maintainer, so an independent project appeal panel is not available. GitHub's abuse process remains separate from project moderation.
