# Workplace journey inventory — code snapshot, 26 September 2026

This is a **dated route-to-journey snapshot** for the Today redesign. Current workflow controls and engineering coverage are in [the owner catalogue](../contracts/next/catalogue.md) and [verification inventory](../status/capability-delivery-matrix.md). It names the business record that should own each action when a user starts from Today, Search, Inbox, AI or an app. `W` means the selected authorized workspace under `/holdings/{holdingSlug}`; its Branch/Department context must be retained where that app supports it. Front POS/PMS and public portals have separate origins and permission boundaries. “Canonical” below is the **recommended owner route**, not a claim that all old links already redirect there.

The inventory comes from page routes, holding API handlers, command schemas, services and the current contracts in this working tree. The original 26 September snapshot counted 166 page routes. The [generated UAT route inventory](../testing/uat-route-inventory.md) now reports the current source count and fingerprint; this dated journey analysis is not the current route count. A present route or command proves an implementation surface, **not** that a new user, every role, mobile, statutory rules, provider integrations or a complete cross-team journey has passed acceptance. This audit did not run each route in a browser or mutate business data.

## Shared entry and handoff rules

Apply the same acceptance lens to **every** row: English interface and Gregorian dates while preserving Thai source documents; THB/Asia/Bangkok where Company policy requires them; mobile touch and keyboard/screen-reader operation; Company/role/source-record access on page, API, file, feed and AI preview; immutable decisions and evidence; and safe refresh, retry, two-tab conflict and offline recovery. A calendar plan, feed reaction or notification state must never change an owner transaction.

### English UI and Gregorian date audit boundary

The targeted code scan covered the new Today/social, Calendar, AI intake, Buy, Expense, Leave and Task entry surfaces. It found no hard-coded Thai UI copy in those surfaces; the UI now uses an explicit English/Gregorian formatter for the browser-default post, calendar history, invitation, request-history, task-routine and leave-balance displays identified in this pass. PromptPay expiry times in the POS/PMS Front components use the business timezone instead of the browser timezone. These are code checks, not multi-browser visual acceptance.

The wider 166-route interface **does not yet meet a verified English-only/Gregorian standard**. `src/lib/shared/front-language.ts` still contains Thai Front UI translations, and `src/components/collaboration/auth-form.tsx` has Thai `frontMode` messages. Browser-default date/number formatting remains in other areas, including People directory/roster, Technology provisioning, Legal reports, Security and Inbox. Native `date`/`datetime-local` controls can also render according to browser or device locale even when their stored value is ISO/Gregorian; test the visible result on Thai-locale mobile and desktop browsers before accepting the standard. This audit did not change Thai source text, uploaded documents, official forms or Thai country policy.
