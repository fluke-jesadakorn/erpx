# Native Directory grants preserve exact scope and current credential evidence

Accepted for native implementation on 2026-10-27; the native source implements retained transaction/session integration, while runtime activation and full Directory migration remain pending. Native Directory reconstruction rejects a Holding grant with a non-null scope node and a Platform grant carrying Branch or Department scope, because dropping or reinterpreting either shape could turn ambiguous recorded intent into broader authority. Ordinary independently reviewed mappings retain the current behavior required by [ADR-025](ADR-025-multiple-identity-providers-and-scoped-replacement.md); the two rejections are explicit compatibility differences, not an assertion that B0 already rejected them.

The unchanged B0 `createIamGrantPolicy` oracle accepts a Holding input with a node because validation ignores that node, and permits a Platform actor's Branch request although the Platform insert has no corresponding scope columns. The retained oracle keeps those results unchanged. Native tests record rejection separately: no node removal, scope relabeling, implicit grant, or legacy import exception is permitted. Fresh synthetic native databases are authorized, so an inconsistent record must be corrected through its owning reviewed workflow before it can participate in a grant.

Credential verification produces a single-use, non-serializable witness bound to the exact Directory Connection, Company, Holding, provider, mode, connection version and private profile generation. Its lifetime is bounded by the existing two-minute sign-in reservation duration from successful provider verification; neither synchronization nor database waits extend that deadline. Provider I/O finishes before retained database leases. A session-first, non-retrying Control command then retains the current configured Holding binding, exact Directory route/configuration, approved Provider Identity and membership, and the actual relevant mapping/parent/role version read set through session commit. Snapshot reconciliation first fixes and verifies intended removals, then captures its upstream mapping/parent/role source before inserting new grants. Bounded exact intended row after-images and the original upstream source remain mandatory through the final commit boundary; neither immediate nor deferred effects may replace the baseline or rewrite the intended recipient/revocation. Session issuance resamples time and rechecks its retained evidence after Holding retirement waits and immediately before acknowledgement. Independently committed Holding tombstones remain monotonic if the later Control command fails.

An observed absence of applicable mappings is a real source result, not a fabricated permission set. Authentication does not itself mint a Business Role or Work context; current scoped assignment and business authorization remain separate checks. Missing current parent, published role, approved membership or required source evidence is never replaced with an empty role, permissive default or local password. Organization owns current node lineage and People owns current Person facts and reviewed links; Identity consumes their borrowed public ports without writing their tables.

This chooses exact recorded scope and current evidence over emulating B0's ignored fields or normalizing malformed records on read. Implementing the decision does not establish full Directory migration, enterprise-provider acceptance, production readiness or permission to activate native routes.
