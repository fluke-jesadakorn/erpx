# Organization arrangement drafts

The People workspace at `/holdings/{holdingSlug}/people` now uses one unit rail, a main list of positions and their occupants, and a detail drawer with expandable sections. Selecting a unit changes the main structure; selecting a person or position opens its details. HR settings and the team schedule open in the same page. The former Source, Tray and Destination layout is retained below as implementation history.

The workspace loads an existing private Company draft with GET and creates a draft only on the first arrangement. Structure and review use the same projected organization. People, positions with their occupants, and departments can be moved with drag handles or the keyboard-accessible “Move…” destination chooser. Pending changes expose Undo/Redo and combined review. Parking preserves an item whose destination is not yet chosen; no employment record changes until submission and the relevant effective-time or approval workflow completes.

Drafts persist in PostgreSQL per owner and Company. Every save checks the version, preview fingerprints the current organization and selected policy defaults, and submission validates that fingerprint again. Changed source records require an explicit rebase and another review. Submitted drafts are immutable through the application; continuation includes only items marked as needing review.

Submission records department approval requests, connected placement groups, reservations, receipts, audit and outbox in one transaction. Related people and positions apply together; independent groups remain independent. Department-dependent groups use the replacement department ID recorded by the existing approval flow. Rejection blocks dependent groups. Effective-time changes or revoked authority stop the group for review, retaining already applied independent changes. Salary remains untouched. Existing organization and engagement triggers prepare IT work separately.

The draft backend previously introduced `0363_organization_drafts.sql` and `0364_organization_draft_baselines.sql`. Those migrations belong to the earlier draft implementation. This single-workspace UI adds no schema migration and does not upgrade installed staging or production.
