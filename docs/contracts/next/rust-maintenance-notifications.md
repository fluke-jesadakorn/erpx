# Native Maintenance notification boundary

The Collaboration-owned writer inserts the original `staff_notifications` row in the caller's existing SERIALIZABLE Holding unit. It preserves the full `maintenance-notice-{outerKey}` ID, Company, Work owner recipient, `maintenance_work` source, intended Work version, exact Created/Updated message and Work `updated_at`. The original 0312 trigger produces its `legacy:` Inbox event and delivery. No additional notification clock, Workflow receipt, personal grant or independent commit is introduced.

The mandatory `PgMaintenanceNotificationSource` supplies original owner-key/action and intended Work-after facts. `require_before` verifies the real current source without advancing the late command version guard; `require_after` verifies the actual intended Work/event after-image. There is no production default. The actual Rust service composition implements this port using Maintenance's sealed Work/plan and immutable data getters; the full cross-owner binding resides in `src/composition`, not the Maintenance package. A source label or copied facts cannot authorize this writer.

Before the first Holding snapshot the source bundle invokes `lock_maintenance_notification_sources` along with its actual owner/IAM/purchase/Workflow sources. This helper provides write-intent ordering only. Preparation derives all three notification/Inbox images before effects. `PreparedMaintenanceNotification::into_owned` moves those original images and unit into `OwnedPreparedMaintenanceNotification` across Workflow prepare/apply without retaining a self reference. Persistence reborrows the real original source, checks exact facts and original database/postmaster/backend/XID, requires actual owner completion, inserts exactly one row and compares the three actual images with the precomputed values. No proof is reconstructed from post-trigger state.

`RetainedMaintenanceNotification` checks only Collaboration's unit and images. The enclosing Workflow separately retains original owner/IAM/purchase/stock proofs and rechecks them and the notification receipt after audit/outbox and deferred triggers. A receipt cannot complete an owner or grant rights. Each retained JSON text image is capped at 8,192 UTF-8 bytes in SQL before transfer; absent, changed, oversized or cross-unit state denies. No notification clock is sampled: the owner supplies its already captured intended Work `updated_at`.

Current scoped verification passes five native pure tests against sixteen exact B0 Node-SQL cases and six migrated PostgreSQL component tests. The latter use an explicitly synthetic owner port and the actual 0312 Inbox trigger; they prove exact images, source rebinding, unit/isolation refusal, retained tuple locks, SQL collision behavior, byte admission and immediate/deferred rollback, without granting Work authority.

The actual Maintenance issue-part command passes all three complete Workflow PostgreSQL cases after relocation to `erpx-service`, including exact replay and whole-command rollback after deferred outbox tampering. The same normal runner, test paths, suite IDs, cases and assertions are retained; earlier executions remain separate pre-move evidence. The relocated service also passes all eight actual Work/source cases. This is a bounded notification integration.
