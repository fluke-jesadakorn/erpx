# Catalogue workflows and ownership

Generated by `bun run status:capabilities` from the module registry, engineering scenario register and scoped delivery references. Replaces the Rust-era domain maps. [Owner contracts](README.md) define detailed HTTP behavior; [verification inventory](../../status/capability-delivery-matrix.md) records evidence separately.

## Shared boundaries

Holding isolation, the current selected Company/Branch/Department assignment, expiring authority and owner permissions apply at command execution and replay. Idempotency, expected versions, independent review where required, immutable source/evidence and transactional audit/outbox are owner controls, not powers granted by a record link or a reaction.

Customer identity, Customer authority and federated Customer 360 projections remain separate. Finance owns cash/GL posting; stock, POS/PMS and source owners retain their own immutable movements. Talent hiring, Learning eligibility, Benefits and payroll consume versioned handoffs rather than duplicating each other's source records. Platform authority does not imply Company data access.

Typed references and AI proposals resolve each supported source through its owner and recheck current access/version on application. Unreadable sources do not become readable through backlinks, conversations, Support or an agent. The current adapters and editable schemas define coverage; the removed plans' promise of chips in every field is not an implementation claim. AI needs human review and cannot silently execute owner commands.

Long forms opened from a page use the right form drawer; dedicated full-page forms remain inline. Current UI behavior is in [Workplace UX](workplace-ux.md).
