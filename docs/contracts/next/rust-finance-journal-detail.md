# Native Finance journal detail read

The unmounted development component exposes GET `/api/v1/holdings/{holdingSlug}/finance/journals/{id}` through `finance_journal_read_router`. Production configuration is rejected until Finance's own release and Company acceptance ports exist. Neither the private development session CLI nor an installed gateway/current Next page mounts this route.

The payload's `data` is the B0 ledger detail contract: `journal`, `lines`, and `history`. Journal columns retain their snake-case names and include People-owned `created_by_name` and `posted_by_name`. Lines retain all journal-line columns plus account `code`/`name`, ordered by ordinal. Immutable draft editions retain their columns, ordered by journal version. The separate GET `/api/v1/holdings/{holdingSlug}/finance/journals/{id}/workspace` returns the B0 `journalRecordWorkspace` data in the same retained read. It adds the actual chart row; all chart/Company accounts ordered by code,id, including inactive accounts; all Company periods ordered by start_date descending,id, including closed/closing periods; active Company dimension definitions ordered by code; and active Company dimension values ordered by code. The last query preserves B0's lack of an additional active-parent-definition predicate. Reference queries do not substitute posting policy. Workflow actions, branding and the current record page remain pending.

Read authorization uses the actual Account/Holding opaque cookie, current configured Control binding, selected grant, Organization lineage, current IAM/People/GPO facts, Finance module admission and `finance.read`. It does not require write, approve, preparer independence, open periods or active posting accounts. Commercial access uses real `finance.accounting` History and revalidates its retained witness; an inactive current purchase may still retain History under the existing owner policy. It is never changed into NewWork/SettleExisting from a receipt shortcut.

The first admitted source scope is explicit: current primary-book, Workflow-origin-backed Finance manual/opening journals and manual-root reversal chains. Every creation/reversal receipt must match the actual Company, creator, record, operation, command-derived journal identity and result. Secondary-book and foreign-owner sources without their native current facts are denied. A source label or a caller-supplied capability cannot grant access. The source adapter runs on the caller's existing SERIALIZABLE unit and never commits, retries or obtains a second connection.

Before IAM establishes the first Holding snapshot, the coordinator acquires the participating Commercial, Workflow, Finance and People source fences. Finance locks cover headers, lines, editions, chart/account names and book relationships, including absence predicates. Positive tuple reads preserve SQLSTATE40001 for older snapshots. Private source proofs bind database, postmaster lifetime, backend and transaction; final checks retain the original source, names and purchase witnesses. No provider, external HTTP effect or long compute occurs in this unit.

People display lookup preserves the exact Company/user relationship: an unmerged Person supplies `legal_name`, regardless of active/engagement state. It does not follow aliases or synthesize a session name. Only actual absence returns `Unlinked account`; corrupt or oversized selected rows deny. Unrelated Company/user metadata is not fetched. Name lookup accepts at most the creator/poster IDs from the already-authorized journal and retains absence sources before the first snapshot.

The response's `context` is a response-only rendering snapshot produced inside the same authorization callback as `data`: original user/Holding/Company, workspace IDs/slugs, selected assignment/version/revision, original grant scope, current role/modules/permissions and expiry. The outer canonical authorizer rechecks current authority and retains its Control lease through the Holding commit. A separate session read is never combined with later owner data. The DTO has no Deserialize path and cannot reconstruct an AuthorizedWorkContext or authorize a mutation.

Both surfaces keep the exact same current read/History policy and captured account/work context; reference data is not fetched in a second request after authorization. The first read can omit CAS headers. If any context header is supplied, the complete exact company/assignment/revision/assignment-version tuple is required and checked against the retained current selection. Workspace branch/department headers are bounded path selectors, resolved through current Organization/IAM; they carry no authority. Cookies reuse the canonical8192-byte/duplicate/audience parser. Exact Host/Holding paths apply; a supplied foreign Origin is rejected. Unknown/unsupported sources receive404; closed persistence failures contain no SQL details. Responses are private/no-store without blanket CORS.

Source rows are SQL-bounded before client collection, including aggregate byte accounting and row limits. The detail admits at most10000 combined rows and2MiB of source JSON, with256KiB per row; the complete response is also counted through a non-allocating bounded serializer before final retention. Original receipt evidence has a separate aggregate4MiB limit and ancestry is limited to100 reversals. These native resource admissions are explicit limits, not a claim of unlimited legacy parity. Wire integers must be exact JavaScript-safe integers. The TypeScript and OpenAPI outputs are generated from the Rust response DTOs, with generators absent from default/release features.

The named server-only detail/workspace frontend adapter is `@erpx/feature-finance/public/server`. It calls one native owner read using one actual asynchronous Next16.4 header snapshot. It forwards only exact Host, bounded Cookie, declared workspace/CAS selectors and read/cache headers. It never performs a preliminary session query or constructs an Actor. Its explicit literal-loopback transport uses a fresh direct Node HTTP agent with empty proxy configuration, no patched fetch/HMR cache, no redirect following and no ambient cookie jar. It caps the streamed response before strict DTO/context/data validation and owns cancellation/deadline cleanup. Supplied expected context is captured before the async read; later caller mutation cannot replace it. No current SSR loader or page is switched.

A configured `DirectoryRefreshRuntime` supplies the same concrete `HoldingWorkAuthorizer` to these reads and the Finance review administration. Stale Directory observation completes outside the Control/Holding business leases, then the normal fresh authorization unit retains the current route, profile generation, session, selection and owner facts. This does not issue a new session or give a Directory snapshot acting authority. The ordinary authorizer constructor keeps its existing behavior.

Actual disposable-PostgreSQL tests cover read-only IAM, original same-unit context, B0 journal/name fields, manual/opening/reversal provenance, retained purchase History, source-writer waits, optional CAS and canonical cookie/Host/Origin denial, selected People corruption/resource limits and detached/local-mutated witnesses. Three further real Finance/LDAPS cases prove the configured Directory path returns the original workspace context, allows an independent current reviewer to post with one receipt/audit/outbox, and refuses a permission withdrawn during provider I/O with no posting effects. An actual NOWAIT check proves Finance leases are absent during that I/O. The actual pinned-Node provider starts only an owned ephemeral Finance listener after in-process Router proof. A normal Account group switch retires the original cookie; the same typed client receives401 for it, then returns owner data with the new account's exact context from a fresh cookie while the original response keeps its original account. Listener, child and transaction cleanup are checked. These are component verification receipts; owner migration and release acceptance remain incomplete.
