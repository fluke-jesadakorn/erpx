# Marketing public intake

Marketing keeps form configuration and preview immutable. A form may reference an exact reviewed content asset revision and a separately approved creative publication owned by that content asset in the same Company. Operators choose these references in the form editor. The public page exposes the approved content and sanitized derivative, with the publication's retained alt text; it never exposes private source files or document links.

Independent form activation checks current content status/version, public approval, bound owner links and available File Sources. The transaction locks referenced content and publication rows and repeats the predicates before committing. Current Console readiness, anonymous page/API reads, internal candidate capture and public submission check the same references. Retiring the content, changing its version or withdrawing the referenced publication makes that presentation unavailable. Form-only intake remains supported when no optional presentation references are selected.

Public intake requires same-origin submission, explicit consent and a stable idempotency key. A submission retains the original form revision, consent timestamp, contact, brief and attribution. The transaction checks current form status/version and presentation before writing the candidate and receipt. It accepts one candidate under response-loss retries and rejects a different request under the same key. A withdrawn presentation prevents both fresh submissions and receipt replay.

A currently authorized person reviews the candidate and invokes the existing CRM handoff. The original candidate and engagement history survive content/media withdrawal; the CRM lead and Marketing touch retain their source reference. Presentation readiness describes these native owner records and public publication state. Provider configuration records and engineering fixtures remain separate from live advertising-provider certification.

`tests/public-marketing-form.test.ts` verifies real native owner writes, private storage, sanitized preview/publication, independent reviews, public consent, retry, CRM handoff and current withdrawal/cross-Company/version guards. Its scanner is a declared integration adapter. `tests/e2e/demo-workplace-platform-lifecycle.spec.ts` uses normal Console identities, the anonymous form and the compiled release's actual scanner on desktop and mobile; final release evidence must record the actual passed cases.
