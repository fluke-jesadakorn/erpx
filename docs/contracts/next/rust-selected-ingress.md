# Native selected Identity ingress component

This internal component establishes a bounded ordering for selected Identity, synchronous schema normalization and ordinary owner authorization in the unmounted [Field Service parts entry](rust-field-service-migration.md). It does not mount HTTP or establish complete transport, SDK, browser, runtime or owner migration parity. The [production plan](../../production-plan.md) retains the full PR1 and subsequent PR2 gates.

## Boundary and ordering

The existing `execute` and `execute_deferred` methods of [FieldServicePartsAdministration](../../../src/composition/src/field_service_parts/administration.rs) retain their current read/write-before-wire behavior. The separate internal `execute_schema_ingress` accepts an already typed Order ID and command key as data; it does not validate raw route identifiers or key transport. It forces a workspace mutation and retains configured Holding/Company scope.

The [Identity authorizer](../../../packages/server-identity_access/src/adapters/authorized_work.rs) obtains an authenticated, current selected context before running the synchronous schema callback. Its borrowed `SelectedWorkIngress` witness exposes selected scope for normalization, not a grant, actor or database connection; it is neither cloneable nor serializable. Only after schema succeeds does ordinary module and read authorization run, followed by the Service entry's explicit write permission and owner command. Scope checks and utility source fences occur before the first Holding snapshot. Those fences grant no rights, and their existence does not claim identical retained B0 lock timing.

The same retained transaction protects currentness through the final check, including the clipped deadline and applicable Directory/Control proofs. A local wire failure does not override revocation, expiry or final time/currentness failure; an absent owner permission does not override a wire failure when selected Identity remains current. Success retains the existing command's receipt, owner checks and rollback behavior. The witness itself does not authorize business effects.
