# Native engineering cohort and compiled Service admission

This is an opt-in isolated verification profile for the already delivered [native Parts](service-parts-native-closure.md) and [Count](rust-service-count-delivery.md) capabilities. It makes a real compiled Service renderer use the same physical native database authority as its Rust API. It does not complete a business owner, replace the public development runtime, or close Field16.

## Identity and transaction boundary

The test lifecycle provisions eight distinct native development leases: Control and three Holding write/read pairs. The existing native lease prefix, token, role, owner, comment and loopback checks remain. A private source/run/release-bound roster and manifest prevent database aliases, copied data, swapped bindings and mixed cases. The ordinary browser-name profile is preserved.

Only the owned network-none PostgreSQL container receives catalog MAINTAIN privileges for its limited fixture role, in each target database. No shared host cluster grant is performed. Fenced typed SQL units begin with catalog SHARE locks before their first SERIALIZABLE snapshot, then verify current file context before commit. Actual PostgreSQL tests prove concurrent comment blocking, later denial, rollback and retained-client reload behavior. No catalog UPDATE/INSERT/DELETE privilege is granted.

These are specific units: typed prepare/batch/transaction and object-lock operations. BetterAuth/Drizzle's direct Control pool, raw Account/IAM transactions and migration pools retain their original boundaries. Marked engineering predicates on unfenced instrumented clients reject. Live lease/OID/owner/comment checks run in the marked Holding predicates; this is not live identity validation for all eight databases on every query, universal authentication-query fencing, whole-request atomicity or a distributed Node/Rust transaction. Native business authorization and transactions remain independently authoritative.
