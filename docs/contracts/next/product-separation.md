## SSO protocol

```text
Product /sso/start -> Account /sso/authorize -> Product /sso/callback
  browser secret       current central          state + PKCE + parent
  state + challenge    session + short grant    -> new product session
```

Browser transactions expire at five minutes; authorization grants expire at 60 seconds or earlier with the browser/parent. Only hashes of browser secrets, states and grant codes are stored. PKCE verifiers stay in a Secure, HttpOnly, SameSite=Lax, host-only transaction cookie. An exact, registry-derived callback, environment, audience, central session and transaction bind the grant. Concurrent callback consumption commits one child; failed verification does not consume the valid grant.

New account-host credential/directory sessions receive audience metadata at creation. Legacy sessions have no binding and cannot become issuer sessions by observing an origin. Product sessions use independent opaque tokens, stored hashed in the existing session table, with immutable metadata and a live-parent join. Their database `createdAt` retains original authentication time so MFA freshness is not renewed by switching products. Expiry is capped by parent expiry and original authentication plus twelve hours; products do not refresh it. No central token reaches an app, URL or browser storage.

Family sign-out requires POST with the exact request Origin. It removes the parent and child session rows, so live session joins reject subsequent reads, callbacks and session-aware queued work. Password reset and independent all-device revocation keep their existing semantics. Holding tombstone propagation, Push/queued-authority regression, account switching, directory provider callback approvals and public portal MFA must still pass the impact gate before activation.

SSO responses use `private, no-store` and `no-referrer`. Callback credentials are removed from the return path. No central cookie has a Domain attribute. Email and successful LDAPS login forms use a document navigation for the validated `/sso/authorize` return, so RSC navigation/refresh cannot consume the single-use exchange twice. OIDC retains its normal provider redirect. Cloudflare uses one exact-host bypass rule for dynamic/private responses, leaving Next static assets, fonts and brand assets on their existing policy. The published-host receipt records DNS/HTTPS/cache and browser landing checks; complete RSC/Company/role/capability isolation and all owner workflows remain broader acceptance work.
