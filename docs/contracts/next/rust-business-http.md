# Native business HTTP component

This component is available only through `erpx-service`'s explicit `business-http` feature. It creates an Axum router for composition tests; no running gateway, API, scheduler or installed service mounts it. Finance production configuration remains rejected until Finance release and Company acceptance ports exist. Owner migration and acceptance flags remain incomplete.

The router receives actual Holding administrations, an exact Account policy and its validated configured-Holding registry, plus requested branch/department selectors. Host and Holding path must match that configuration. The request parser reuses the canonical Account cookie parser, including its aggregate 8192-byte budget, duplicate-name rejection across Cookie headers and audience-specific opaque token. Parsed cookie data grants no authority.

Every Holding session, SSO start/authorization/consumption, interactive Work inspection and queued preparation/retention checks the current Control `holding_bindings` source against the configured Holding ID, slug and read/write/files binding names. Configuration is never derived from the mutable row. Session-bearing operations acquire session-first source fences before their first Control snapshot; queued phases retain a separate short non-retrying Control read lease around the owning Holding unit. The private binding witness checks database, postmaster lifetime, backend, transaction and exact current row. SQLx-managed transactions are required. An old SERIALIZABLE snapshot preserves SQLSTATE40001 at its positive tuple fence. No Control lease, binding proof or authorized context crosses provider computation.

Mutations require all four headers: `x-erpx-context-company`, `x-erpx-context-assignment`, `x-erpx-context-revision` and `x-erpx-context-assignment-version`. Revision is a canonical nonnegative safe integer; assignment version is a canonical positive safe integer. Missing, duplicate, malformed or stale context is denied. Only these four bounded values are captured, and validation occurs after actual retained session authentication. They are selectors checked against current sources, never a serialized Actor or permission grant.

Finance POST routes are `/api/v1/holdings/{holdingSlug}/finance/journals/{journalId}/post` and `/reverse`. Post returns200 and reversal201, both with a `data` envelope. A supplied foreign Origin is denied; missing Origin retains the existing Finance behavior. The body is bounded to2MiB and decoded without requiring Content-Type. Current Finance read/module admission precedes body/schema/idempotency errors; actual write, approver, same-Person, source, purchase and final authority checks remain in the canonical Finance administration. Unknown body properties are stripped before hashing. Integral numeric forms such as1.0 and1e0 normalize identically. Reversal memo absence and empty string remain distinct, while null is invalid.

Finance's sealed normalized command retains exact ECMAScript JSON for Workflow receipt identity and a separate UTF-8 view for SQL storage. Accepted lone UTF-16 therefore cannot collide with replacement text even when both have the same stored UTF-8 text. There is no public raw-JSON/hash override. The retained Node26.11.1 corpus checks45 actual B0 wire outcomes; real PostgreSQL HTTP tests cover auth ordering, current source checks, exact replay and rollback.

Legal OCR/verification POST routes are `/api/v1/holdings/{holdingSlug}/legal/documents/{documentId}/ocr` and `/verify`. They require the exact Holding Origin and Idempotency-Key, ignore request bodies and Content-Type, and return200 with the current queued receipt in `data`. All18 retained body/content-type combinations use actual Account/IAM/Commercial/Legal queue composition in the PostgreSQL test. Record membership, current mutation context and real owner policy apply before replay. No blanket CORS policy is added.

Failures have private no-store responses. Persistence errors use a closed generic500 response without SQL details; unknown hosts, retired hosts, mismatched Holding paths and unavailable records receive a generic404. Actual provider readiness, durable worker recovery, general production bootstrap, broader Finance source ownership and frontend business SDK/SSR cutover remain separate incomplete work. The bounded wire fixture is a compatibility oracle, not acceptance evidence.
