# Native Finance parts draft boundary

The Finance-owned parts bridge prepares a non-opening DRAFT journal and its `operational_inventory_consumption` `stock_cost` Money evidence inside the original borrowed Holding transaction. The Rust service composition root assembles the actual Maintenance owner source, Inventory/Quality/Finance facts, Commercial purchase, Workflow and Collaboration ports in `src/composition/src/maintenance_parts.rs` and its private `maintenance_parts/source.rs`. Maintenance retains its Work policy, SQL, facts and owned plan/receipt. The assembly grants neither `finance.write` nor stock/source authority. Field Service remains data-only until its owner/reservation protocol exists.

`lock_owned_parts_draft_sources` acquires journal, lines and Money write intents before Finance facts and Inventory view/planner locks, all before the current IAM Holding snapshot. The utility lock is ordering infrastructure; the source and final image proofs remain mandatory.

`prepare_owned_parts_draft` completes actual Journal and Money preparation before the Workflow known-result receipt. The bridge reads its write clock exactly for Journal and Money preparation; it preserves the earlier consumption time. In the complete command, the original order is Work application time → consumption time after period selection → Journal time → Money time → Workflow receipt/audit/outbox time. A separate guard clock observes current authority without consuming any of those write timestamps. The notification uses Work `updated_at`, not the later consumption or receipt time. The full outer key through 180 bytes keeps the literal `:parts` journal identity suffix; this is an identity seed, not a second command key or receipt.

The original preparation checks chart/account/Money errors before the later mapping/owner version guards. Provisional `MAX_SAFE_INTEGER+1` source version is data only, so a missing quote still precedes the owner's late version refusal. Amounts, quantities and stored timestamps retain safe bounds. Sixteen byte-checked B0 scenarios and seven native pure tests cover identity, Unicode, timestamps and this ordering; synthetic oracle ports establish no database authority.

The private-constructor states preserve the original transaction and intended Finance after-images:

1. `PreparedPartsDraft::into_owned` moves the original Journal/Money preparation and immutable facts binding across Workflow prepare/apply without a source borrow, new quote or authority refresh.
2. `OwnedPreparedPartsDraft::persist_journal` reborrows the actual owner, verifies exact original facts/unit and invokes its late `require_apply` before persistence.
3. The owner writes consumption/lot evidence, then `persist_stock_cost` writes the retained Money; the owner subsequently writes stock and Work/event effects.
4. `RetainedPartsDraft::into_finance_receipt` first verifies the complete actual owner after-image, then moves the original unit, predetermined Journal image, Money proof and expected IDs into an owned Finance-only receipt.
5. The enclosing Workflow checks that receipt plus its separately retained original Work/Inventory/Commercial/IAM and notification proofs after audit/outbox and deferred triggers. A receipt cannot authorize or prove completion of another owner.

The existing borrowed API delegates to the same persistence path. No opaque state implements Clone or deserialization, and no public proof constructor, owner label grant, post-trigger rebaselining or independent commit is available.

Scoped verification passes seven Finance pure tests and fresh post-relocation executions of all eight actual Maintenance source/owned-state PostgreSQL cases and all three complete Workflow PostgreSQL cases. The latter now execute in `erpx-service` through the unchanged normal runner; test paths, suite IDs, cases and assertions remain under `tests/integration/maintenance`. Earlier receipts are retained separately as pre-move evidence. These cases retain current Account/Holding authority and real Commercial, Work, Inventory, Finance and Collaboration effects: one owner receipt, exact replay, distinct clock observations, all three notification/Inbox images, original maximum-version error order and complete rollback after deferred outbox tampering. The pure oracle's synthetic ports establish data/error-order compatibility only. The real command uses `records.write`; it does not synthesize `finance.write` for the issuer.

This completes a bounded issue-part DRAFT command component. Independent Finance posting still needs actual foreign-owner source/purchase/readiness ports and a Finance reviewer; generic reversal must retain `REVERSE_AT_SOURCE`. Field Service, other Maintenance actions, full production release qualification and current UI/runtime cutover remain pending. All 41 owner completion flags remain false, and this boundary activates no route, scheduler, listener or current page.
