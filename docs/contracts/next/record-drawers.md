# Record drawers

Registers and owner catalogues open records in a right drawer while retaining the current list, search, filters, cursor and scroll. Document identifiers/names are explicit links. Shared tables add a View details action only to rows containing an owner record link. Row clicks ignore other controls, modifiers and text selection. Input, comparison and fictional presentation tables remain ordinary tables.

`src/lib/records/record-drawer.ts` defines typed owner references and full-page routes. `detailKind`, `detailId`, `detailArgs` and `detailPage` preserve selection, report predicates and source pagination in the URL. Static module routes and creation/print links remain navigation. Console's parallel `@record` slot reads IDs directly, reuses existing detail pages, and supplements modules without a dedicated page through owner services. POS, PMS and Administration collections use their existing authorized GET surfaces with `workFetch`, request cancellation and context revision checks. Front and Platform retain their independent scope/projection rules.

The shared drawer uses `Dialog presentation="form-drawer"`, a fixed header and a scrolling body. Mobile fills the viewport width. Existing form drawers render inline when embedded; command validation, record versions, status transitions and write/approve permissions remain owned by the existing module. Input changes guard close, another record, full-page navigation and browser Back. Dirty state tracks individual edited forms: saving another form or an attachment does not discard an unfinished editor. A successful owner command refreshes the view and register. Closing restores focus to the originating register control, including after following a related record or replacing the register's rendered links. Loading, denied/not-found, changed report sources and retry states stay inside the drawer.

Aggregate readers retain the source owner's predicates and page source records in groups of 30: product/warehouse stock, currency/month payroll, historical aging buckets, financial statement accounts/journals, budget dimensions, saved report rows, cash forecast invoice cohorts, PMS hotel-day and control-account sources, POS receipt reports, Marketing attribution, usage/billing groups, and Executive metric groups. Executive sources use the same trusted owner SQL and selected label/unit/filter cohort. Retained financial report snapshots remain immutable; current source drill-down returns a conflict when its source fingerprint differs. Redacted Platform executive observations remain redacted rather than granting access to underlying Holding business records.

The generated [inventory](record-drawer-inventory.json) records the 33-module adapter map, current table sources, classifications, reviewed helper delegation and record collection/catalogue surfaces. Run `bun scripts/ui/record-inventory.mjs`; a missing table trigger fails the command. This is a source coverage register, not a claim that all populated browser states have been accepted. Browser observations and screenshots live under ignored `.scratch/record-drawers/`; empty development scopes do not prove populated editor behavior.

Owner-level tests cover direct IDs outside list pages, pagination, report cohort totals, historical source conflicts, Company/Branch/Department denial and URL/filter preservation. Final acceptance also requires actual development browser behavior, typecheck/lint, UI guard, relevant integration/E2E and an isolated release build. Health is checked only on local development, public development and private production; staging is excluded.

The [development verification receipt](record-drawer-verification.md) separates implemented source coverage, populated browser checks, empty scopes and checks awaiting an authenticated Front session.
