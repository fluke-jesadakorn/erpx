# Master Data, Import, Reporting, and Search Requirements

These shared capabilities preserve distributed domain ownership. They do not
create a central master-data bounded context or an alternate command path.

## Distributed master and reference data

| ID | Title | Normative requirement | Rationale | Acceptance paths | Source | Scenarios |
|---|---|---|---|---|---|---|
| REQ-MDM-001 | Domain authority | ERPX shall assign each master/reference dataset to one bounded-context owner. | A central catalog must not become duplicate authority. | Success: catalog names owner and commands; Denial: shared service cannot edit source; Failure: unknown owner blocks publication. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-45 |
| REQ-MDM-002 | Reference descriptor | ERPX shall publish stable code, label, scope, classification, state, version, and effectivity descriptors. | Consumers need bounded semantics. | Success: active descriptor resolves deterministically; Denial: hidden values/counts are absent; Failure: invalid descriptor is quarantined. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-MDM-003 | Effective dating | ERPX shall prevent ambiguous overlapping effective versions within an authority scope. | Historical transactions need reproducible meanings. | Success: one version resolves for a date; Denial: overlap is rejected; Failure: gap is explicit rather than silently defaulted. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-MDM-004 | Hierarchical containment | ERPX shall enforce tenant, holding, company, and branch containment for reference publication and inheritance. | Child customization cannot escape its parent. | Success: permitted inheritance resolves; Denial: sibling override is rejected; Failure: ambiguous ancestry fails closed. | [ADR-013](../../adr/ADR-013-holding-branch-database-and-directory-authority.md) | E2E-02, E2E-48 |
| REQ-MDM-005 | Code stability | ERPX shall preserve immutable technical identities when labels or business codes change. | References must survive renaming. | Success: old transactions resolve same identity; Denial: code reuse for another identity is rejected; Failure: conflicting rename requires correction. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-50, E2E-68 |
| REQ-MDM-006 | Lifecycle | ERPX shall govern draft, approve, activate, suspend, retire, and archive states for reference entries where the owner permits. | Shared values need explicit availability. | Success: valid transition publishes state; Denial: consumers cannot activate data; Failure: retire with active dependency is blocked or governed. | [FSD-003](../decisions/FSD-003-enterprise-suite-expansion.md) | E2E-25 |
| REQ-MDM-007 | Dependency check | ERPX shall expose authorized incoming use before a destructive reference change. | Retirement can break transactions. | Success: permitted dependency summary is accurate; Denial: hidden counts do not leak; Failure: unavailable dependency index blocks destruction. | [FSD-005](../decisions/FSD-005-collaboration-references-and-agents.md) | E2E-52, E2E-68 |
| REQ-MDM-008 | Translation | ERPX shall version English, Thai, and locale-specific labels without altering technical identity. | Bilingual UX needs stable meaning. | Success: locale fallback is explicit; Denial: unapproved translation is not published; Failure: missing translation uses governed fallback. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-17 |
| REQ-MDM-009 | Distribution | ERPX shall distribute reference changes through versioned events and rebuildable projections. | Consumers need decoupled updates. | Success: ordered updates converge; Denial: consumer cannot write source through projection; Failure: gap triggers replay. | [ADR-002](../../adr/ADR-002-cqrs.md) | E2E-16, E2E-68 |
| REQ-MDM-010 | Reference audit | ERPX shall preserve authority, before/after version, effectivity, actor, approval, and consumer reconciliation evidence. | Reference changes have broad impact. | Success: authorized audit reconstructs change; Denial: protected values are redacted; Failure: missing evidence blocks certification. | [FSD-001](../decisions/FSD-001-baseline-and-governance.md) | E2E-25 |

## Reporting and export

| ID | Title | Normative requirement | Rationale | Acceptance paths | Source | Scenarios |
|---|---|---|---|---|---|---|
| REQ-RPT-001 | Governed report definition | ERPX shall version report measures, dimensions, filters, owners, classification, and source contracts. | Reports must have defined semantics. | Success: execution pins definition; Denial: unauthorized definition is hidden; Failure: incompatible source version blocks run. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-002 | Interactive report | ERPX shall execute interactive reports only against authorized read models with declared freshness. | Reporting must not bypass CQRS. | Success: result declares cutoff/provenance; Denial: row/field/count leakage is absent; Failure: stale source is labeled or blocked by policy. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-003 | Saved report | ERPX shall save report configuration without freezing broader authority than the creator currently has. | Saved filters are not access grants. | Success: reopen reauthorizes sources; Denial: shared report reveals no hidden filter values; Failure: retired definition prompts migration. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-004 | Scheduled report | ERPX shall run schedules under a governed non-human identity and re-evaluate recipients and access at execution. | Schedules outlive user sessions. | Success: eligible recipients receive output; Denial: revoked recipients are excluded; Failure: authority uncertainty stops delivery. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-005 | Export formats | ERPX shall support governed CSV, XLSX, PDF, and internal API representations. | Stakeholders need portable outputs. | Success: formats preserve declared semantics; Denial: unsupported/unsafe format is rejected; Failure: rendering error produces no partial authoritative file. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-006 | Asynchronous bulk job | ERPX shall execute large exports as bounded resumable jobs with progress, cancellation, and expiry. | Bulk work must not block interactive requests. | Success: completed job produces one manifest; Denial: unbounded request is rejected; Failure: worker restart resumes safely. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-007 | Secure download | ERPX shall deliver exports through short-lived, audience-bound, audited authorization. | Export files concentrate data. | Success: intended recipient downloads before expiry; Denial: replay/other recipient is rejected; Failure: revocation invalidates outstanding access. | [ADR-005](../../adr/ADR-005-global-read-auditing.md) | E2E-24 |
| REQ-RPT-008 | Provenance manifest | ERPX shall attach definition, parameters, scope, source positions, freshness, generated time, actor, and digest to every export. | Outputs need reproducibility. | Success: manifest verifies file; Denial: recipient cannot alter provenance; Failure: incomplete manifest blocks verified label. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-009 | Approval | ERPX shall require approval for report/export classes designated high-risk by policy. | Sensitive bulk access needs independent review. | Success: approved exact request executes; Denial: changed request invalidates approval; Failure: expired approval blocks run. | [ADR-005](../../adr/ADR-005-global-read-auditing.md) | E2E-24 |
| REQ-RPT-010 | BI extract | ERPX shall publish governed BI extracts with classification, owner, schema version, incremental cursor, and deletion propagation. | External analytics must remain controlled. | Success: consumer advances cursor idempotently; Denial: unapproved fields are absent; Failure: gap triggers bounded replay. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-24 |
| REQ-RPT-011 | Retention | ERPX shall expire report jobs and files under classification, customer, jurisdiction, and legal-hold policy. | Exports must not persist indefinitely. | Success: eligible file deletes with evidence; Denial: hold blocks purge; Failure: object deletion mismatch remains open. | [FSD-004](../decisions/FSD-004-thailand-and-sector-overlays.md) | E2E-24, E2E-31 |
| REQ-RPT-012 | Export audit | ERPX shall audit preview, generation, approval, download, cancellation, expiry, and deletion without logging exported content. | Bulk access needs oversight. | Success: events correlate to manifest; Denial: ordinary users cannot inspect others; Failure: evidence gap blocks completion claim. | [ADR-005](../../adr/ADR-005-global-read-auditing.md) | E2E-24 |

## Governed import

| ID | Title | Normative requirement | Rationale | Acceptance paths | Source | Scenarios |
|---|---|---|---|---|---|---|
| REQ-IMP-001 | Versioned template | ERPX shall publish a versioned import template with owner, fields, semantics, constraints, and target command. | Imports need stable contracts. | Success: supported template is discoverable; Denial: retired template cannot commit; Failure: incompatible version yields migration guidance. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-002 | Safe upload | ERPX shall bound, digest, classify, scan, encrypt, and tenant-scope import files. | Files are untrusted inputs. | Success: safe file receives immutable digest; Denial: malware/oversize file is quarantined; Failure: scanner outage prevents processing. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-003 | Dry run | ERPX shall validate an import without issuing business commands and return row-level deterministic findings. | Users need preview before mutation. | Success: same inputs/policy produce same findings; Denial: dry run cannot alter state; Failure: unavailable authority marks validation incomplete. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-004 | Authorization preview | ERPX shall evaluate scope and command authority for every proposed row before approval. | File possession is not write authority. | Success: eligible rows identify target command; Denial: unauthorized rows disclose no hidden target; Failure: authority change invalidates preview. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-005 | Approval | ERPX shall pin file digest, template, dry-run result, actor, scope, and command policy in import approval. | Approval must cover exact content. | Success: approved batch is immutable; Denial: changed file requires new approval; Failure: expired approval blocks commit. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-006 | Typed commands | ERPX shall commit imports only by invoking the authoritative typed command for each accepted row or batch. | Imports cannot become a database backdoor. | Success: source receipts link rows; Denial: direct table writes are unavailable; Failure: command rejection remains row evidence. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-007 | Atomicity policy | ERPX shall declare whether an import is all-or-nothing or independently atomic by row/group. | Partial success must be predictable. | Success: outcome follows declared mode; Denial: undeclared partial commit is rejected; Failure: restart resumes without duplicates. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-008 | Reconciliation | ERPX shall reconcile every accepted row to command receipt and resulting authoritative state. | Submission is not completion. | Success: row reaches accepted/rejected outcome; Denial: importer cannot mark success manually; Failure: missing outcome enters work queue. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-009 | Correction | ERPX shall correct imported business state through source-domain reversal/correction rather than file-row deletion. | Audit forbids history rewriting. | Success: correction links original row; Denial: committed row cannot be erased; Failure: closed-period policy blocks unsafe correction. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-25 |
| REQ-IMP-010 | Import evidence | ERPX shall retain template, digest, validation, approval, commands, results, corrections, and deletion evidence. | Bulk mutation needs complete traceability. | Success: authorized reviewer traces each row; Denial: source data is redacted by role; Failure: evidence gap prevents verified completion. | [FSD-001](../decisions/FSD-001-baseline-and-governance.md) | E2E-25 |

## Federated search

| ID | Title | Normative requirement | Rationale | Acceptance paths | Source | Scenarios |
|---|---|---|---|---|---|---|
| REQ-SRC-001 | Authorized projections | ERPX shall search only disposable projections built from authorized typed descriptors. | Search must not query source databases indiscriminately. | Success: results link source positions; Denial: hidden records/counts are absent; Failure: unavailable index is explicit. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-23 |
| REQ-SRC-002 | Field authorization | ERPX shall apply field authorization before tokenization, indexing, matching, snippets, facets, and ranking. | Post-filtering can leak hidden data. | Success: authorized field contributes; Denial: protected field leaves no observable match; Failure: policy uncertainty excludes it. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-23 |
| REQ-SRC-003 | Typed result | ERPX shall return record type, opaque reference, authorized label, scope summary, state, freshness, and canonical resolver. | Users need safe, actionable results. | Success: result opens `/reference/item/:id`; Denial: restricted metadata is redacted; Failure: moved route resolves after refresh. | [FSD-006](../decisions/FSD-006-clean-rebuild-architecture-and-cutover.md) | E2E-23, E2E-50 |
| REQ-SRC-004 | Principal search | ERPX shall separate human, agent, group, and agent-pool search with capability and hierarchy filters. | Mention targets have different effects. | Success: eligible types are labeled accessibly; Denial: hidden directory entries/counts are absent; Failure: stale membership blocks fan-out. | [FSD-005](../decisions/FSD-005-collaboration-references-and-agents.md) | E2E-48, E2E-55, E2E-56 |
| REQ-SRC-005 | Business-record coverage | ERPX shall index every cataloged first-class aggregate root and no internal line/event unless its parent policy permits anchored search. | Coverage must be explicit and safe. | Success: catalog and index types match; Denial: internal checkpoint is unavailable; Failure: missing type fails validation. | [FSD-005](../decisions/FSD-005-collaboration-references-and-agents.md) | E2E-23, E2E-68 |
| REQ-SRC-006 | Freshness | ERPX shall expose index freshness and prevent unsafe commands from stale search results. | Discovery can lag authority. | Success: fresh result is actionable after reauthorization; Denial: stale result grants no action; Failure: unknown freshness shows degraded state. | [ADR-002](../../adr/ADR-002-cqrs.md) | E2E-16, E2E-23 |
| REQ-SRC-007 | Deletion propagation | ERPX shall propagate erasure, tombstone, retention purge, access revocation, and reference redaction to search. | Search copies must not outlive authority. | Success: bounded propagation removes content; Denial: deleted snippets cannot remain; Failure: lag blocks affected results until reconciled. | [FSD-005](../decisions/FSD-005-collaboration-references-and-agents.md) | E2E-23, E2E-53, E2E-68 |
| REQ-SRC-008 | Rebuild | ERPX shall rebuild search from source descriptors and content projections without mutating authoritative state. | Index recovery must be safe. | Success: rebuild converges at source cursor; Denial: search worker cannot issue business commands; Failure: gap stops publication. | [ADR-002](../../adr/ADR-002-cqrs.md) | E2E-16, E2E-68 |
| REQ-SRC-009 | Query audit | ERPX shall audit sensitive search purpose, scope, actor, query digest, result classes, and outcome without storing raw secrets. | Discovery of restricted data needs oversight. | Success: authorized audit explains access; Denial: ordinary users cannot inspect queries; Failure: missing purpose blocks protected search. | [ADR-005](../../adr/ADR-005-global-read-auditing.md) | E2E-23 |
| REQ-SRC-010 | Bounded query | ERPX shall bound query length, complexity, page size, cursor, rate, and wildcard behavior. | Search must resist abuse and enumeration. | Success: valid query pages stably; Denial: abusive query is throttled without hidden counts; Failure: invalid cursor is rejected. | [FSD-002](../decisions/FSD-002-shared-platform-capabilities.md) | E2E-23 |
